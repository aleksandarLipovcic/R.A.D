# Project R.A.D

Project R.A.D (Remote Aerial Dashboard) is a small ground-control-station (GCS) and telemetry frontend for hobby flight controllers (Betaflight style) and u-blox NEO-M10 GNSS modules. It provides a threaded C++ backend (DroneLink) exposing telemetry via pybind11 to a Tkinter-based Python GUI (DroneCockpitUI).

This repository includes:
- DroneBackend: C++ backend (Windows), serial MSP comms, UBX passthrough helpers, GPS parsers.
- DroneCockpitUI: Python Tkinter GUI that visualizes attitude, GPS position, satellites, map tiles, and diagnostics.
- Documentation files under the repo root (analysis, architecture, quick reference).

## Prerequisites

- Microsoft Visual Studio Community 2022/2026 (recommended) or MSVC toolchain
- Python 3.8+ (3.10 recommended) and pip
- pybind11 (the C++ project links against it; the build includes submodule or system install)
- On Windows: Windows SDK and C++ desktop development workload


## Build (C++ backend)

1. Open the Visual Studio solution in `DroneBackend/` with Visual Studio 2022/2026.
2. Configure the solution for x64 Debug (or Release) and build the `DroneBackend` project.
3. After a successful build, copy `DroneBackend.pyd` (or ensure it is placed into `DroneCockpitUI/x64/Debug`) so the Python UI can import it.


## Python UI — run locally

1. Ensure the built `DroneBackend.pyd` is on `sys.path` (e.g., copy it into `DroneCockpitUI/x64/Debug` or modify `DroneTest.py` to append the path).
2. Install runtime Python dependencies (if any). The UI is pure Tkinter; additional packages for tile fetching use the standard library.
3. Run the test script to verify the bridge:

```powershell
python DroneCockpitUI/DroneTest.py
```

4. Start the main UI (use the launcher script or run the main module in DroneCockpitUI).


## Running with real hardware

- Connect Betaflight FC to the PC via USB and set the proper COM port.
- Ensure Betaflight configurator is closed so the backend can talk MSP to the FC.
- The DroneLink backend polls MSP frames and populates `DroneState` exposed to Python.
- Satellite data is polled via MSP command 164 (MSP_GPS_SV_INFO) and updated roughly every 1s.

Troubleshooting: if the GPS widget shows "no data" but the GPS position fields and satellite count are present:
- Verify in the Python `state` object that `sv_info_valid` is True and `sv_source` is "MSP".
- Inspect `state.sv_list` (a list of SVInfoEntry objects). The UI should call `state.to_dict()` or `state.sv_list` and pass that to the widget. See `QUICK_REFERENCE_SATELLITES.md` for examples.


## Development notes

- The primary GPS parser is in `DroneBackend/GPSneoM10.cpp` and the binding layer is `DroneBackend/Bindings.cpp`.
- Satellite polling is handled by `DroneBackend/DroneLink.cpp` (polls every ~1s at a 100 Hz loop rate).
- For UI issues, check `DroneCockpitUI/GPSWidget.py` where satellite lists are normalized and rendered.
